# Git with parallel sessions

Several sessions work the same repos at once, and each one commits and pushes its own work. That shapes every git command.

- **Commit with `git add -- <your paths>`, then `git commit --only -- <your paths>`, then push**, once the change is verified. The add is needed because `--only` refuses a new file git doesn't know yet. A path you removed with `git rm` skips the add, which fails on it; `--only` still commits the deletion. A message file comes from `mktemp`, never a fixed name like `msg.txt`: subagents share one scratchpad, and on 31 Oct one overwrote another's message mid-commit. An agent isolated in a worktree has its own folder, so it writes the paths out literally and the message to a fixed file inside that worktree: a `$M` message file or a `${FILES[@]}` path array gets the git call refused (5 refusals across one 8-agent run, 9 Nov 2026). It leaves everyone else's staged and unstaged work alone. Never `git add -A` or `git commit -a`. The hook's `vp staged` `git add`s any file another session writes while it formats, staged or not, which carried 2 files into `--only` commits on 10 Nov 2026 (client-glance b9245c19, to-sheets 4ad9fe1b6), so the managed hook now refuses that commit and names the paths: run the same commit again.
- **Your hunks in a file another session also edits go through a private index**: `GIT_INDEX_FILE=$(mktemp)`, `git read-tree HEAD`, `git add` the whole file, then `git apply --cached -R --unidiff-zero` their hunks cut from `git diff HEAD -U0` (a bare `git diff` under the private index compares against it, finds nothing and fails with `No valid patches`, 3 Nov 2026), `write-tree`, `commit-tree -p "$B"`, `git update-ref HEAD <new> "$B"` with `B=$(git rev-parse HEAD)` taken at the `read-tree`, so the update refuses when HEAD moved and you redo it on the new HEAD (a stale private index reverted another agent's 10 iOS files, 3 Nov 2026), then `git reset -q -- <path>` when the real index still holds that path's previous commit: otherwise it sits staged as a revert of your commit, and the next session's `git commit` undoes it (2 Nov 2026, 3 files). `commit-tree` runs no pre-commit hook, so run the repo's gates on the private index first (`GIT_INDEX_FILE=<it> node ~/Studio/upsys/kit/packages/lint/bin/heyramzi-repo-rules.js`), then build a `git worktree add` of the new tree: the working tree still holds the lines you left out, so only that build shows a missing one (a new module committed without its `index.ts` export broke two add-ons, 4 Nov 2026). Forward-applying a hand-picked subset lands later hunks on shifted lines (28 Oct 2026), and a plain `git commit` after `git apply --cached` takes everyone's staged hunks: on 27 Oct 2026 it pushed a half-built free plan that broke main.
- **A rejected push, or local main behind origin, gets `~/Studio/upsys/kit/scripts/git-sync-main.sh <repo>`**: it replays your commits onto origin in a temp worktree, pushes, and moves main while keeping everyone's uncommitted edits. Never `--autostash`: it re-applies another session's edits over the new commits and leaves files conflicted, so `command-guard` refuses it. Never drop a stash that holds another session's work. In vibe-kit the script first regenerates every repo's rule copies from the tip it pushes: the sync writes them from HEAD, and with main behind origin's `shell.md` change the push gate refused 20 repos on every run (10 Nov 2026).
- **Another session may stash your uncommitted work mid-turn**, so a file you just wrote reads as reverted and `git status` is clean. Take your paths back with `git checkout stash@{0} -- <paths>` and leave the entry for its owner.
- **`Unable to create '.git/index.lock': File exists` means another session's git command is running.** Wait a few seconds and rerun yours. Delete the lock only when `pgrep -x git` finds nothing, because removing a live one corrupts that session's index.
- **Never stash somebody else's uncommitted file to test something.** `stash push -- <path>`, then `checkout` and `drop`, leaves the file at HEAD and their work in a dangling commit you can only find by grepping `git fsck --unreachable`. Copy the file to the scratchpad and test there. A module that imports packages or a `#` subpath like `#secrets` can't find them from the scratchpad (`ERR_MODULE_NOT_FOUND`, 3 Nov 2026; `ERR_PACKAGE_IMPORT_NOT_DEFINED`, 7 Nov 2026), so run it from its own folder or test that one in a `git worktree add "$(mktemp -d)/tree" HEAD` with its install. A module that imports `cloudflare:workers` loads in neither place under plain `node` (`ERR_MODULE_NOT_FOUND` on a scratchpad copy of `commands/index.ts`, 10 Nov 2026): compare its output through a vitest test or the running dev server's route.
- **Two agents never edit one generated catalog at once** (a `.xcstrings`, a lockfile, a schema JSON). Each save rewrites the whole file and drops the other's entries: a Bookmarks agent's catalog save wiped an archive agent's 5 strings mid-run (Wavenote, 6 Nov 2026). Brief one agent to own the file, and give the other the strings to hand over.
