# Testing

**Tests are E2E first, and you don't write unit or integration tests on your own.** A test you write is your reading of the intent, same as the code, so it can't catch you misreading it. On 25 Sep 2026 we cut back the unit suite on every website for restating the code. Outside evals agree: on SWE-bench Verified (arXiv 2602.07900), cutting agent-written tests left success flat and cut input tokens by a third or more.

- E2E is the test you write: Playwright on the web, XCUITest on Apple. Writing it is part of the change. Running it isn't, see below.
- **A product goes to production with every UI interaction and every API command covered by a spec** (Ramzi, 10 Nov 2026): the app keeps a coverage matrix of its routes, form actions and commands, and a guard fails a new one that has no spec. Locameublé's is TSK-2209.
- A unit or integration test needs a source outside your head. That's test cases Ramzi wrote or named, or a bug that really happened, reproduced as a failing test before the fix (`diagnose` owns that). Anything else, look at it running (the page, the row, the log) or say what's unproven.
- **A test that compares dev config to deployed config (wrangler, env bindings) stays when you cut a suite.** E2E runs against dev and can't see that drift, so the 25 Sep audit restored `platform-proxy-config.test.ts` after a worker cut it.
- **A bug a user hit ships with the spec that catches it, unasked.** Run it red on the old code, green on the fix, in the same commit: reproducing that bug is the job, so this run carries `E2E_JOB=bug`. Ramzi had to ask for the login "Sending..." spec (5 Nov 2026).
- **Check what you changed: `check-changed <your paths>`, or `check-changed --staged`.** It lints those files, finds the tests that import them with a static import scan and runs only those, and typechecks only your files and what they import, then reports only errors in your files. `vp test related` is refused: it transforms every test file first, 3.3 GB and 10 minutes in upsys/app (27 Oct 2026). A whole-repo `svelte-check`, `pnpm check` or `vp test run` is refused: upsys/app's svelte-check needs a 3 to 4.6 GB heap, and 3 at once filled 16 GB of swap (26 Oct 2026). A change that truly needs the whole repo (a shared type, a config, a dependency bump) prefixes `FULL_CHECK=1`.
- **The differential check is the only check before a commit or push, in every Studio repo.** That's `check-changed <your paths>` and nothing else: no Playwright run, no `check-changed --e2e`, no spec rerun after a review fix. Ramzi, 16 Nov 2026: *"Ça ne sert à rien de changer quatre fichiers de code pour ensuite refaire toute une batterie de test avant de push."* The same week in immo, agents and the session ran 9 specs before a small change and he had to stop them. A spec runs only when running it is the job: you're writing or fixing that spec, or reproducing a bug a user hit. Then name the spec and prefix the opt-in, `E2E_JOB=spec playwright test e2e/a.spec.ts` or `E2E_JOB=bug ...`; `command-guard` refuses any Playwright run, `pnpm test:e2e` or `--e2e` without it. A whole suite stays refused even then (one spec held a gate slot for 11 minutes while every vitest run waited, 26 Oct 2026), and after a failure `--last-failed` reruns only what broke.
- **Rerunning is free when nothing changed, and a failure reruns alone.** `check-changed` remembers a pass by your files' contents, so asking again about them, or any of them, skips straight to `pass`: a hook's `--staged`, upsys's `--warnings` pre-commit and the next session reuse your run. Each step prints its peak memory, and the last line the run's, so a check that grew shows. A failed add-on E2E test reruns by title, `vp test run --config <cfg> <file> -t "<title>"`, never its suites whole: 3 failures cost a 26-test, 25-minute rerun (Ramzi, 29 Oct 2026). `--force` is for a flaky server, not for reassurance.
- **A test under Vitest's jsdom environment reads a fixture with `join(import.meta.dirname, "<path>")`, never `new URL("<path>", import.meta.url)`.** jsdom swaps the global `URL`, so `readFileSync` throws `The URL must be of scheme file` and `.pathname` resolves to `/<path>` (og-image walk, then the Marketplace parser test, 16 Nov 2026). Node-environment tests and Playwright specs are fine either way.
- **Vite+ runs the tests, never `npx vitest`.** Vite+ is the whole toolchain (Ramzi, 22 Oct 2026), and since `vp migrate` most packages no longer install `vitest` at all.
