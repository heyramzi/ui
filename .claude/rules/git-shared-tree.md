# Git with parallel sessions

Several sessions work the same repos at once, and each one commits and pushes its own work. That shapes every git command.

- **Commit with `git add -- <your paths>`, then `git commit --only -- <your paths>`, then push**, once the change is verified. The add is needed because `--only` refuses a new file git doesn't know yet. An agent isolated in a worktree has its own folder, so it writes the paths out literally and the message to a fixed file inside that worktree: a `$M` message file or a `${FILES[@]}` path array gets the git call refused (5 refusals across one 8-agent run, 9 Nov 2026). It leaves everyone else's staged and unstaged work alone.
- **Your hunks in a file another session also has dirty go through `~/Studio/upsys/kit/scripts/git-commit-mine.mjs`.** Before your first edit to a file `git status` already shows modified, run `git-commit-mine.mjs snapshot --id <you> <paths>`. When done, `git-commit-mine.mjs commit --id <you> -m <message-file> <paths>` (`--dry-run` shows the diff first). It applies your diff since the snapshot onto HEAD's version through a private index, runs `heyramzi-repo-rules` on it, moves HEAD only if nobody else did (retrying once), resets the real index, and leaves the working tree alone. A path with no snapshot commits whole. Exit 3 means your edit sits on their lines: commit it with `--whole <path>` or move it. Doing this by hand cost 4 Swift agents their last 15 turns in one day (TSK-3580, 25 Nov 2026), and a stale private index once reverted another agent's 10 iOS files (3 Nov 2026). Then build a `git worktree add` of the new commit: the working tree still holds the lines you left out, so only that build shows a missing one (a new module committed without its `index.ts` export broke two add-ons, 4 Nov 2026). In a SvelteKit app that worktree typechecks against the live checkout's route types when its `node_modules` links there (Kit keeps its tsconfig in `node_modules/$app`), so copy `$app` into the worktree first, as the push gate does: without it a clean tree showed 38 false errors (immo, TSK-3037, 17 Nov 2026). Link every `node_modules` from the main checkout into it first, the way `git-sync-main.sh` does (`ln -s <main>/<dir>/node_modules <tree>/<dir>/node_modules` per folder): a gate script run in a bare tree died `Cannot find package '@heyramzi/lint'` (immo `check-monopole.mjs`, TSK-3346, 23 Nov 2026). Forward-applying a hand-picked subset lands later hunks on shifted lines (28 Oct 2026).
- **A rejected push, or local main behind origin, gets `~/Studio/upsys/kit/scripts/git-sync-main.sh <repo>`**: it replays your commits onto origin in a temp worktree, pushes, and moves main while keeping everyone's uncommitted edits. Never `--autostash`: it re-applies another session's edits over the new commits and leaves files conflicted, so `command-guard` refuses it. Never drop a stash that holds another session's work. In vibe-kit the script first regenerates every repo's rule copies from the tip it pushes: the sync writes them from HEAD, and with main behind origin's `shell.md` change the push gate refused 20 repos on every run (10 Nov 2026).
- **Another session may stash your uncommitted work mid-turn**, so a file you just wrote reads as reverted and `git status` is clean. Take your paths back with `git checkout stash@{0} -- <paths>` and leave the entry for its owner.
- **`Unable to create '.git/index.lock': File exists` means another session's git command is running.** Wait a few seconds and rerun yours. Delete the lock only when `pgrep -x git` finds nothing, because removing a live one corrupts that session's index.
- **Never stash somebody else's uncommitted file to test something.** `stash push -- <path>`, then `checkout` and `drop`, leaves the file at HEAD and their work in a dangling commit you can only find by grepping `git fsck --unreachable`. Copy the file to the scratchpad and test there. A module that imports packages or a `#` subpath like `#secrets` can't find them from the scratchpad (`ERR_MODULE_NOT_FOUND`, 3 Nov 2026; `ERR_PACKAGE_IMPORT_NOT_DEFINED`, 7 Nov 2026), so run it from its own folder or test that one in a `git worktree add "$(mktemp -d)/tree" HEAD` with its install. A copy of part of `~/Studio` breaks the same way: `tools/edit/node_modules/@heyramzi/review` is a relative link into the sibling `ui` repo, so an Editor OS build in a scratch Studio copy without `ui` beside it said `ERR_MODULE_NOT_FOUND` (16 Nov 2026). A worktree whose `node_modules` is a symlink to the main checkout's runs binaries by path (`node_modules/.bin/vp`, `wrangler`), never `pnpm exec` or an install: pnpm rewrote 55 `.bin` scripts in the main apple-apps checkout to the worktree's path (16 Nov 2026). A module that imports `cloudflare:workers` loads in neither place under plain `node` (`ERR_MODULE_NOT_FOUND` on a scratchpad copy of `commands/index.ts`, 10 Nov 2026): compare its output through a vitest test or the running dev server's route.
- **Two agents never edit one generated catalog at once** (a `.xcstrings`, a lockfile, a schema JSON). Each save rewrites the whole file and drops the other's entries: a Bookmarks agent's catalog save wiped an archive agent's 5 strings mid-run (Wavenote, 6 Nov 2026). Brief one agent to own the file, and give the other the strings to hand over. A shared UI test file is the same trap: 6 parallel Leonida agents each added a step to `ReviewPassTests.swift`, and two hit `already exists in index` and `would be overwritten by checkout` (TSK-3448, 23 Nov 2026). Brief each agent to put its test in its own new file (`ReviewPassCheatsTests.swift`), never append to a suite another agent is editing.
- **Deploy from a worktree only once your commit is on origin/main, and log the deploy to a file named after your ticket.** A deploy replaces the whole Worker: two Leonida agents deployed uncommitted worktrees 20 seconds apart, and the second dropped the first's 13 collections for 13 minutes. Both wrote `> <scratchpad>/deploy.log`, which sibling subagents share, so the first read the second's `worktrees/tsk3525/.../web/build` line as its own and reported a wrangler bug that wasn't there (TSK-3529, 24 Nov 2026).
