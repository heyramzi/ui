## 1. CSS layers

### Design (decided)

- **One kit layer: Tailwind's own `components`.** No new layer name. A new name can't sit between `base` and `utilities`: layer order is first-declared order, so a `kit` layer first declared after Tailwind's `@layer theme, base, components, utilities;` lands *after* `utilities` and beats every utility. LayerChart (a kit dependency) already does exactly this: `node_modules/layerchart/dist/styles/core.css` opens with `@layer theme, base, components, utilities;` and puts its rules in `@layer components`.
- **Every kit stylesheet opens with the order statement** `@layer theme, base, components, utilities;`, then wraps its style rules in `@layer components { ... }`. Why: component CSS reaches the page as separate chunks (JS `import "x.css"` and Svelte `<style>`), and in a build a chunk can load before the app's `app.css`. If a kit chunk declared `components` first, the order would become `components, theme, base, utilities` and Tailwind's preflight (`base`) would beat kit components. Repeating the same 4-name statement is a no-op when Tailwind came first and fixes the order when it didn't.
- **Where the order is declared for consumers:** Tailwind's `@import "tailwindcss"` already declares it. `tokens/index.css` (imported right after) adds the same statement as line 1 so the contract is written down in the kit. Nothing changes in a consumer's `app.css`.
- **Svelte `<style>` blocks:** put the statement and an `@layer components { }` block inside `<style>`. Verified with svelte 5.57.3 `compile()` (scratch test, `css: "external"`): rules inside `@layer` get scoped (`.a.svelte-1lj1c24`), `:global(.d)` inside the layer comes out unscoped inside the layer, `@media` nested in the layer is scoped, keyframes are renamed `svelte-<hash>-name` whether inside or outside the layer, `@keyframes -global-x` stays `x`, `@property` passes through, unused-selector pruning still works. The extra `.svelte-hash` specificity no longer matters across layers.
- **`:global(...)`:** goes inside the layer block like any rule.
- **`@keyframes`:** stay at top level (layers only matter for keyframe name clashes, and Svelte prefixes scoped ones). `-global-` keyframes stay top level.
- **`@property`:** stays at top level (Tailwind also emits it unlayered).
- **`@theme`, `@theme inline`, `@utility`, `@custom-variant`, `@source`, `@import`:** Tailwind directives, stay top level and untouched. `@layer utilities { .x {} }` in a Tailwind-processed file becomes `@utility x {}` so variants work.
- **Token variable blocks stay unlayered** (`:root`, `.dark` in `tokens/palette.css`, `tokens/craft.css`). Two consumer scripts parse those files by top-level selector: `~/Studio/agency-os/app/src/components/shared/provider-icon/tokens.node.ts` (`/^(:root|@theme( inline)?)$/` on top-level blocks) and `~/Studio/upsys/app/scripts/generate-brand-manifest.ts`, `check-token-consolidation.ts`, `src/lib/server/brand-kits.ts`. Wrapping them breaks those. Variables don't fight utilities anyway.
- **Component-local `:root` var blocks** (animations, canvas, sheet) go inside the layer: an app's unlayered `:root` override then always wins.
- **`prefers-reduced-motion` block in `tokens/base.css` stays unlayered with its `!important`.** In layers `!important` order inverts (an earlier layer's important wins), so moving it would change who wins. It's meant to beat everything.

### What breaks for a consumer

- Any `class=` an app passes to a kit part that the kit's own CSS was silently overriding starts applying. That's the point, but it is a visual change in every app: a stale `bg-*`, `p-*` or `rounded-*` left on a kit part will now show. Release step: screenshot pass per app (section 8).
- App CSS in its own `@layer components` now ties with the kit and is decided by specificity, then order. Unlayered app CSS always wins.
- `charts/charts.css` repaints LayerChart's tooltip and is unlayered on purpose to beat LayerChart's `@layer components`. Inside the layer it ties: keep the `[data-variant="default"]` attribute selectors (0,2,0) and confirm LayerChart's own selectors on `.lc-tooltip-container` are lower before moving it; otherwise raise specificity, don't leave it unlayered.
- `~/Studio/upsys/website/src/routes/(frontend)/[lang=lang]/products/[slug]/+page.svelte:239` wraps `RichRenderer` in `prose prose-gray`. Typography utilities will now beat `editor/content.css`. Check that page by eye after the bump.

### Changelog draft (Breaking changes)

```markdown
## [3.0.0](https://github.com/heyramzi/ui/compare/ui-v2.24.0...ui-v3.0.0) (2026-11-DD)

### Breaking changes

`node ~/Studio/upsys/kit/scripts/ui-upgrade-codemod.mjs <dir>` rewrites the mechanical cases and lists the rest.

* Kit CSS sits in Tailwind's `components` layer. A class you pass to a kit part now beats the part's own styles, so a stale `bg-*` or `rounded-*` left on a kit part will show. Screenshot your main pages after the bump.
* Change callbacks are `on<Prop>Change`: `onValueChange` on `StarRatingInput` and `TagsInput`, `onContentChange` on `RichEditor` and `DocEditorPage`, `onDocChange` on `InlineEditor`, `onTitleChange` for `ontitle`, `onIndexChange` on `Deck`, `onModeChange` on `ThemeProvider`, `onDatesChange` on `TaskGantt`, `onHoveredIndexChange` on `Legend` and `RingChart`, `onShowAuthorNamesChange` on `EditedChip`.
* `SidePanel` takes `onOpenChange(open)` in place of `onClose()`.
* Every other callback is camelCase: `onSelect`, `onRemove`, `onCopyLink`, `onExit`, `onReady` and the `DocMenu` actions (`onMove`, `onDelete` and the rest).
* The package root is gone. Import effects from `./effects/<name>`, all as named exports: `import { Marquee } from "@heyramzi/ui/effects/marquee"`. `./border-beam` and `./theme-toggle` are gone too.
* One path per name: `DataPanel` is `DetailPanel` from `./components/list-page`, `SectionLabel` comes from `./components/section-header`, `CountChip` from `./components/chip`, `revealTheme` from `./lib/theme-transition.js`, `PILL_TINT` is `TONE_TINT` from `./lib/tone.js`, and `tryCatch` from `./lib/result.js`.
* `./work/kanban`, `./work/list`, `./work/gantt`, `./work/time`, `./work/detail`, `./editor/serializer`, `./onboarding/stores` and `./lib/*` without `.js` are gone. Use `./work`, `./editor`, `./onboarding` and `./lib/<name>.js`.
* The demos left the package: `./work/demo`, `./work/docs-demo.svelte`, `./work/detail-demo.svelte`, `./record/demo.svelte`, `./slides/demo`, `./slides/demo-slides`, `./onboarding/demo` and `./agents/demo.svelte`. They live on the docs site.
* `./design` now loads the same craft and primitives CSS as `./tokens.css`, without the palette. Radii step 6, 10, 14, 18 and 22px, so controls, cards and overlays round a little more.
* `FilterItem` renders a menu item inside a `DropdownMenu`: checkbox items keep `checked`, radio items take a `RadioGroup` value.
* `.shadow-soft*` are Tailwind utilities, so `hover:shadow-soft-md` works.
```

## Risks (top 3)

1. **The layer change flips the cascade in all 33 consumers at once.** Classes that were dead on kit parts come alive, xyflow and LayerChart overrides drop to a tie, `prose` beats `editor/content.css` on upsys/website product pages, and a kit stylesheet that ever ships without the order statement lets preflight beat the kit. No codemod can see this: it needs the CSS gate test plus a screenshot pass per app.

3. **Breadth of the import rewrite in upsys/app plus the `TagsInput` combobox swap.** About 45 `DataPanel` imports, the root removal (which `build-dist.mjs` must survive), default-to-named on 8 effects, and the largest swap landing in a part used by 5 apps including the Solusign client app.
